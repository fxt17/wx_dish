# 家庭点菜与冰箱管理小程序

一个基于微信原生小程序开发的家庭饮食管理项目，将菜谱、随机点菜、时令筛选和冰箱库存联系起来：先决定吃什么，再检查缺什么，补齐食材后确认菜单并扣减库存。

项目从微信云开发 QuickStart 模板演进而来，通过微信云开发实现家庭厨房共享。“下单”表示提交家庭菜单，不涉及在线支付、商家接单或配送。

> 云端功能代码已接入，首次启动不再填充示例数据。需要先完成数据库权限配置和 `kitchenApi` 部署，再在“我的”登录、创建或加入厨房。当前通过了本地模拟测试和页面编译检查，真实云端及双账号真机联调仍待完成。详见 [部署与数据保存说明](docs/CLOUD_SYNC.md)。

## 功能概览

### 家庭厨房共享

- 在“我的”登录，创建厨房，或通过邀请码加入已有厨房。
- 同一厨房共享菜谱、库存、分类、购物车、菜单、评价汇总，以及骰子设置和位置。
- 数据保存到云端；前台约每 10 秒同步，返回页面时刷新，也可以手动刷新。
- 本机保留未确认提交和编辑草稿；断网后可重试，版本冲突不会直接覆盖他人的修改。
- 新厨房从空数据开始；退出登录不删除已经保存的厨房数据。

### 菜谱与点菜

- 按分类浏览、按名称搜索菜品。
- 新增、编辑、删除菜谱，设置图片、描述、分类、所需食材及烹饪步骤。
- 在菜品列表或详情页选择菜品，通过购物车查看、取消选择或提交菜单。
- 当前每道菜最多选择一份；提交新菜单时，会提示是否替换已有菜单。
- 完成菜单后可在菜品详情中进行“好吃 / 不好吃”评价，并展示好评信息。

### 时令标识

- 为菜品设置适宜食用的起止月份，支持跨年范围，例如 `12月—次年2月`。
- 使用通用双列选择器，左列提示“当年”，右列根据月份关系显示“当年”或“次年”。
- 点菜页在菜品卡片右上角显示“当季”标识。
- 未设置时令的旧菜品默认按全年适宜处理，也会参与“仅当季”的随机筛选。

### 随机点菜骰子

- 可拖动的悬浮骰子，规则和位置随厨房共享保存。
- 普通点击播放逐渐减速的 3D 骰子动画，停稳后展示随机结果。
- 长按 **3 秒**打开设置，长按过程中显示环形进度，完成时尝试触发轻微震动。
- 可勾选参与随机的分类、设置各分类菜品数量，以及启用“仅当季”筛选。
- 数量不能超过该分类当前可选菜品数；没有候选菜品的分类不可勾选。
- 同一次抽取不会重复选择同一道菜；未配置规则时默认随机一道菜。
- 结果弹窗点击“取消”不改变购物车，点击“确认”才将结果合并到购物车。

### 冰箱与缺料清单

- 新增、编辑、删除食材，记录数量、单位、分类、图片、购买日期、生产日期和保质期。
- 按分类或名称筛选库存，展示剩余保质天数及过期状态。
- 提交菜单后生成缺料清单和待消耗清单，此时不扣除库存。
- 新增、修改或删除食材后，由云端重新计算当前菜单的缺料和待消耗清单，并同步给厨房成员。
- 重新计算时排除过期食材，并合并同名、同单位的可用库存。
- 缺料清单为空时，可在冰箱的菜单面板中确认菜单，按到期时间从早到晚扣除库存。

### 分类管理

- 分别管理菜品分类与食材分类，支持新增、修改、删除和排序。
- 长按拖拽手柄约 **0.5 秒**后进入拖拽，降低误触概率。
- 拖到列表边缘时自动滚动，越靠近边缘滚动越快；首尾位置有渐变高亮提示。
- 返回上一页或点击保存时，将分类名称及顺序提交云端，未提交内容保留本机草稿。
- 重命名同时迁移已有菜品/食材的分类；仍被引用的分类不能直接删除。

## 使用流程

1. 完成云端部署，在“我的”登录并创建或加入厨房。
2. 分别建立菜品、食材分类。在“点菜”页添加菜谱，填写食材用量、单位和时令。
3. 在“冰箱”登记库存，确保名称、单位与菜谱要求一致，并填写有效日期。
4. 手动选菜，或用骰子随机选择并确认加入共享购物车，再提交家庭菜单。
5. 在冰箱查看缺料清单并补齐库存；新增、修改、删除食材都会触发重新核算。
6. 食材齐备后点击“确认菜单”，云端完成库存扣减和菜单归档，成员随后可评价菜品。

这里有两个不同的确认动作：随机结果“确认”只加入点菜购物车；冰箱中的“确认菜单”才会实际扣除库存。

## 本地运行

### 1. 导入项目

1. 克隆或下载本仓库。
2. 使用微信开发者工具导入**仓库根目录**，即包含 `project.config.json` 的目录。
3. 使用你有权限的小程序 AppID，不要直接沿用仓库中的项目身份配置。
4. 检查项目目录配置：小程序目录为 `miniprogram/`，云函数目录为 `cloudfunctions/`。
5. 首次可使用与仓库一致的基础库 `3.17.0` 进行调试；切换版本后请重新检查关键交互。

小程序前端没有 npm 构建流程，不需要 `npm run dev`。根目录 `npm test` 仅运行本地测试；云函数依赖在上传部署时安装。

### 2. 检查云环境配置

当前环境集中配置在 `miniprogram/config/cloud.js`，值为 `cloud1-d1g20bvre49cb67cb`。使用自己的项目时，应填写自己有权限且与小程序关联的环境。

按照 [云端部署说明](docs/CLOUD_SYNC.md) 创建六个业务集合、设置客户端禁止直接读写、配置私有图片存储，再上传 `cloudfunctions/kitchenApi/`。仅编译前端不能完成云端部署。

`cloudfunctions/quickstartFunctions/` 是保留的模板示例，主要业务不依赖该函数，也不会自动清空它使用的集合。当前不提供绕过登录的纯本地业务模式。

`project.private.config.json` 中的同名配置会覆盖公共项目配置，调试时也应检查该文件。

### 3. 编译体验

默认入口为 `pages/menu/menu`，底部导航可切换“点菜”“冰箱”“我的”。

首次显示空状态。在“我的”创建厨房并添加分类、菜谱和食材后再验证功能；不会自动导入旧版分类/骰子缓存或固定示例数据。

建议同时在模拟器和真机检查长按、拖拽、自动滚动、震动反馈及骰子动画。模拟器或不支持震动的设备不一定产生震动反馈。

## 数据与计算规则

### 全局状态

| 字段 | 用途 |
| --- | --- |
| `dishes` | 菜谱、点菜数量、时令及评价信息 |
| `ingredients` | 冰箱食材与库存批次 |
| `orderList` | 已提交的当前菜单，保留菜品数量和食材用量快照 |
| `shortageList` | 当前菜单缺少的食材，条目包含 `name`、`count`、`unit` |
| `consumeList` | 当前菜单计划从库存消耗的食材，结构同上；不是已经扣除的库存 |

`dishCount` 用于点菜购物车，提交菜单后会清零。已提交菜单独立保存数量和食材用量，不随之后清空购物车或编辑菜谱而改变。

### 食材匹配与保质期

- 食材按**名称与单位同时相同**进行匹配。目前不做同义词识别，也不自动换算 `g / kg` 或 `mL / L`。
- 例如菜谱要求 `木耳 200g`，库存中的 `木耳 0.2kg` 不会自动视为等量库存。
- 保质截止日期以生产日期为基准；未填写生产日期时使用购买日期，再加上保质期天数。
- 未填写保质期时，当前代码采用分类默认值：蔬菜、水果、蛋奶 7 天，肉类 30 天，酒水 60 天，其他分类 3 天。这些是程序默认值，不是食品安全建议，应按商品标签填写。
- 早于当天的截止日期显示已过期；当天及未来 3 天内到期显示提醒。
- 缺料与待消耗清单由云函数根据菜单快照及最新有效库存重新计算，计算本身不会扣库存。
- 冰箱页的 `submitMenu()` 请求云端 `order.complete`，事务中检查并扣减库存，重复请求不会重复扣料。

### 时令范围

时令保存在 `dishSeason` 中，包含 `startMonth` 和 `endMonth`，范围为 `1～12`，起止月份都包含在内。

- 起始月份小于或等于结束月份：按当年范围判断，例如 `3～5月`。
- 起始月份大于结束月份：按跨年范围判断，例如 `12月～次年2月`。
- 起止月份相同：仅该月份；`1～12月` 或未配置时令：全年适宜。
- 当季展示和本机随机候选依据设备月份；云端保存随机规则时按北京时间校验。设备日期不准时可能出现差异，应先校准时间。

## 数据保存

| 数据 | 当前保存位置 | 进程重启后 |
| --- | --- | --- |
| 分类及顺序、菜谱、时令、库存 | 厨房云端状态 | 登录后恢复 |
| 点菜购物车、当前菜单 | 厨房云端状态 | 登录后恢复，全体成员共享 |
| 缺料与待消耗清单 | 根据云端菜单和库存实时计算 | 每次读取重新核算 |
| 随机规则、骰子位置 | 厨房云端状态 | 登录后恢复，全体成员共享 |
| 评价汇总、下单次数 | 厨房云端状态 | 登录后恢复 |
| 已完成菜单、评价明细 | 云端独立归档集合 | 保留，历史页面待实现 |
| 已保存的菜谱/食材图片 | 云存储 | 通过成员校验后读取 |
| 未确认操作、编辑草稿 | 分账户和厨房的本机缓存 | 本机可恢复，不跨设备共享 |

本机业务缓存使用分区键：

```text
kitchen:<环境ID>:<用户ID>:<厨房ID>:<数据类型>
```

只有收到云端成功确认的内容才算完成共享保存。断网或版本冲突时，可在“我的”重试或保留草稿后重新编辑。冷启动必须先联网验证身份；清除缓存会丢失尚未上传的本机草稿，但不会删除已保存的厨房云数据。

## 当前限制与后续方向

- **厨房管理**：每位用户一个厨房；创建者暂不能退出或转让，暂无解散和移除成员界面。
- **容量与同步**：单厨房最多 300 道菜、1000 个库存批次、30 位成员，状态上限 600000 字节；采用前台轮询，不是实时推送。
- **冲突处理**：保护旧版本不覆盖新数据，暂不自动合并编辑；未确认写入需要手动重试。
- **历史与清理**：已归档菜单/评价暂无历史页面；旧云图片、本机图片草稿暂不自动清理。
- **扫码入库**：目前只提示尚未接入，不具备商品识别能力。
- **单位换算与食材标准化**：补充等价单位换算及统一食材标识，减少名称、单位不一致造成的缺料提示。
- **测试与发布准备**：完成真实云端部署、双账号真机联调、备份策略及配额费用检查。
