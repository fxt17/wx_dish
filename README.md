# 家庭点菜与冰箱管理小程序

一个基于微信原生小程序开发的家庭饮食管理项目，将菜谱、随机点菜、时令筛选和冰箱库存联系起来：先决定吃什么，再检查缺什么，补齐食材后确认菜单并扣减库存。

项目从微信云开发 QuickStart 模板演进而来，目前主要业务在小程序本地运行。“下单”表示提交家庭菜单，不涉及在线支付、商家接单或配送。

> 当前版本仍处于开发阶段。菜谱、冰箱库存、菜单及评价主要保存在运行内存中，尚未实现完整的本地持久化或云端同步。小程序进程重新启动后，这些数据会重新加载 `app.js` 中的示例值；请勿将其作为唯一的数据记录。

## 功能概览

### 菜谱与点菜

- 按分类浏览、按名称搜索菜品。
- 新增、编辑、删除菜谱，设置图片、描述、分类、所需食材及烹饪步骤。
- 在菜品列表或详情页选择菜品，通过购物车查看、取消选择或提交菜单。
- 当前每道菜最多选择一份；提交新菜单时，会提示是否替换已有菜单。
- 完成菜单后可在菜品详情中进行“好吃 / 不好吃”评价，并展示好评信息。

### 时令标识

- 为菜品设置适宜食用的起止月份，支持跨年范围，例如 `12月—次年2月`。
- 使用通用双列选择器，左列提示“当年”，右列根据月份关系显示“当年”或“次年”。
- 点菜页在菜品卡片右上角显示“当季”标识。
- 未设置时令的旧菜品默认按全年适宜处理，也会参与“仅当季”的随机筛选。

### 随机点菜骰子

- 可拖动的悬浮骰子，位置保存在本机。
- 普通点击播放逐渐减速的 3D 骰子动画，停稳后展示随机结果。
- 长按 **3 秒**打开设置，长按过程中显示环形进度，完成时尝试触发轻微震动。
- 可勾选参与随机的分类、设置各分类菜品数量，以及启用“仅当季”筛选。
- 数量不能超过该分类当前可选菜品数；没有候选菜品的分类不可勾选。
- 同一次抽取不会重复选择同一道菜；未配置规则时默认随机一道菜。
- 结果弹窗点击“取消”不改变购物车，点击“确认”才将结果合并到购物车。

### 冰箱与缺料清单

- 新增、编辑、删除食材，记录数量、单位、分类、图片、购买日期、生产日期和保质期。
- 按分类或名称筛选库存，展示剩余保质天数及过期状态。
- 提交菜单后生成缺料清单和待消耗清单，此时不扣除库存。
- 修改已有食材或删除食材后，重新计算当前菜单的缺料和待消耗清单；返回冰箱页面时显示更新结果。
- 重新计算时排除过期食材，并合并同名、同单位的可用库存。
- 缺料清单为空时，可在冰箱的菜单面板中确认菜单，按到期时间从早到晚扣除库存。

### 分类管理

- 分别管理菜品分类与食材分类，支持新增、修改、删除和排序。
- 长按拖拽手柄约 **0.5 秒**后进入拖拽，降低误触概率。
- 拖到列表边缘时自动滚动，越靠近边缘滚动越快；首尾位置有渐变高亮提示。
- 返回上一页时保存分类名称及顺序，并写入本地缓存。

## 使用流程

1. 在“点菜”页添加菜谱，填写每道菜所需食材的名称、用量和单位，可同时设置时令。
2. 在“冰箱”页登记已有食材，确保名称、单位与菜谱要求一致，并填写有效日期。
3. 手动选择菜品，或点击骰子随机选择并确认加入购物车。
4. 提交菜单，查看库存不足提示；可以确认继续提交，随后在冰箱查看缺料清单。
5. 按需补充库存。修改已有食材或删除库存记录后，缺料与待消耗清单会同步重新计算。
6. 食材齐备后，在冰箱页打开菜单面板并点击“确认菜单”，完成库存扣减，之后可评价菜品。

这里有两个不同的确认动作：随机结果“确认”只加入点菜购物车；冰箱中的“确认菜单”才会实际扣除库存。

## 本地运行

### 1. 导入项目

1. 克隆或下载本仓库。
2. 使用微信开发者工具导入**仓库根目录**，即包含 `project.config.json` 的目录。
3. 使用你有权限的小程序 AppID，不要直接沿用仓库中的项目身份配置。
4. 检查项目目录配置：小程序目录为 `miniprogram/`，云函数目录为 `cloudfunctions/`。
5. 首次可使用与仓库一致的基础库 `3.17.0` 进行调试；切换版本后请重新检查关键交互。

当前小程序前端没有根目录 npm 构建流程，不需要在仓库根目录执行 `npm install` 或 `npm run dev`。

### 2. 检查云环境配置

`miniprogram/app.js` 的 `onLaunch()` 中仍包含模板遗留的 `wx.cloud.init()`，其中 `env` 是直接填写的环境标识。

- 使用云开发时，应将实际传给 `wx.cloud.init()` 的 `env` 改为自己的云环境 ID。
- 只修改 `globalData.env` 不会生效，因为当前初始化没有读取这个字段。
- 如果仅体验本地业务且暂不使用云开发，可在自己的运行配置中暂时停用云初始化分支；不要移除初始化菜谱、库存的 `globalData` 部分。
- `cloudfunctions/quickstartFunctions/` 是独立的模板示例，包含 OpenID、二维码及 `sales` 集合操作；主要点菜、冰箱业务并不依赖部署该示例函数。

`project.private.config.json` 中的同名配置会覆盖公共项目配置，调试时也应检查该文件。

### 3. 编译体验

默认入口为 `pages/menu/menu`，底部导航可切换“点菜”“冰箱”“我的”。

项目内置示例菜谱和库存；示例食材日期固定，可能已经过期。测试缺料计算前，请检查购买日期、生产日期和保质期。默认菜品分类中还保留了用于滚动调试的数字分类，可在分类管理中调整。

建议同时在模拟器和真机检查长按、拖拽、自动滚动、震动反馈及骰子动画。模拟器或不支持震动的设备不一定产生震动反馈。

## 数据与计算规则

### 全局状态

| 字段 | 用途 |
| --- | --- |
| `dishes` | 菜谱、点菜数量、时令及评价信息 |
| `ingredients` | 冰箱食材与库存批次 |
| `orderList` | 已提交的当前菜单，保留菜品数量和食材用量快照 |
| `shortageList` | 当前菜单缺少的食材，条目包含 `name`、`count`、`unit` |
| `consumeList` | 当前菜单计划从库存消耗的食材，结构同上；不是已经扣除的库存 |

`dishCount` 用于点菜购物车，提交菜单后会清零。已提交菜单独立保存数量和食材用量，不随之后清空购物车或编辑菜谱而改变。

### 食材匹配与保质期

- 食材按**名称与单位同时相同**进行匹配。目前不做同义词识别，也不自动换算 `g / kg` 或 `mL / L`。
- 例如菜谱要求 `木耳 200g`，库存中的 `木耳 0.2kg` 不会自动视为等量库存。
- 保质截止日期以生产日期为基准；未填写生产日期时使用购买日期，再加上保质期天数。
- 未填写保质期时，当前代码采用分类默认值：蔬菜、水果、蛋奶 7 天，肉类 30 天，酒水 60 天，其他分类 3 天。这些是程序默认值，不是食品安全建议，应按商品标签填写。
- 早于当天的截止日期显示已过期；当天及未来 3 天内到期显示提醒。
- `syncOrderIngredients()` 会刷新保质状态，按最新有效库存重新计算两份清单，计算本身不会扣库存。
- 实际库存扣减在冰箱页的 `submitMenu()` 中执行，优先使用更早到期的可用批次。

### 时令范围

时令保存在 `dishSeason` 中，包含 `startMonth` 和 `endMonth`，范围为 `1～12`，起止月份都包含在内。

- 起始月份小于或等于结束月份：按当年范围判断，例如 `3～5月`。
- 起始月份大于结束月份：按跨年范围判断，例如 `12月～次年2月`。
- 起止月份相同：仅该月份；`1～12月` 或未配置时令：全年适宜。
- 当季判断依据设备当前月份，而不是云端时间。

## 数据保存现状

| 数据 | 当前保存位置 | 进程重启后 |
| --- | --- | --- |
| 菜品分类、食材分类及顺序 | 模块状态 + 本地 Storage | 正常情况下可恢复；清除缓存后恢复默认值 |
| 随机点菜规则 | 本地 Storage | 正常情况下可恢复 |
| 骰子悬浮位置 | 本地 Storage | 正常情况下可恢复 |
| 菜谱、时令、冰箱库存 | `app.globalData` | 重新加载示例数据，不保留本次修改 |
| 点菜购物车、当前菜单、缺料与待消耗清单 | `app.globalData` | 不保留 |
| 评价与菜品下单次数 | `app.globalData` | 不保留本次修改 |
| 用户选择的图片 | 当前数据中的临时文件路径 | 尚无持久化保存或云上传保障 |

当前使用的本地缓存键：

```text
miniprogram_dish_categories
miniprogram_ingredient_categories
miniprogram_random_dish_settings_v1
miniprogram_random_dish_position_v1
```

这些缓存只保存在当前设备，不代表跨设备同步或云端备份。

## 组件复用

| 组件 | 复用方式与职责 |
| --- | --- |
| `doublePicker` | 在页面 JSON 注册后，以 `<double-picker>` 包裹触发区域；支持左右标题、选项范围、选中索引和外部样式类；通过 `columnchange`、`change`、`cancel` 事件交互 |
| `randomDishPicker` | 接收 `dishes`、`categories` 和长按时长；管理手势、设置和结果；确认时发出包含 `dishIds` 的 `confirm` 事件，由页面更新购物车 |
| `cart` | 展示尚未提交的点菜购物车 |
| `shoppingCart` | 展示冰箱页的缺料、待消耗清单和已提交菜单 |
| `counter` | 菜品选择与取消选择入口 |
| `tabBar` | 点菜、冰箱、我的之间的底部导航 |

## 当前限制与后续方向

- **完整数据保存**：接入菜谱、库存、菜单、评价的本地持久化及云端同步。
- **图片持久化**：替换仅保存临时路径的方式，完善图片存储与恢复。
- **分类关联维护**：目前修改或删除分类不会自动迁移已有菜品、食材的分类字段，需要手动调整相关条目。
- **扫码入库**：界面已有扫码入口，但 `editIngredient` 调用的 `searchIngredient(code)` 尚未实现，不能视为可用的商品识别功能。
- **个人中心**：“我的”页面当前仅保留导航，没有完整的用户资料、登录或账户功能。
- **库存一致性**：新增食材仍使用原有的缺料增量更新逻辑，尚未统一到编辑、删除时使用的重新核算入口；新增过期食材等边界场景仍需完善。
- **单位换算与食材标准化**：补充等价单位换算及统一食材标识，减少名称、单位不一致造成的缺料提示。
- **测试与发布准备**：补充可重复运行的自动化测试、更多真机兼容性验证，并清理模板标题、云环境配置及调试数据。

## 建议验证清单

仓库目前没有统一的自动化测试入口；云函数模板中的 `npm test` 仍是占位脚本，不能作为业务测试通过的依据。

- [ ] 新增、编辑菜谱后，列表、详情及当季标识同步更新。
- [ ] 时令选择覆盖普通范围、跨年范围、单月和全年。
- [ ] 骰子点击、拖动、长按互不误触；结果取消不改购物车，确认才加入。
- [ ] 随机数量不能超过候选数量，无候选分类不可选择。
- [ ] 分类首尾拖拽、边缘滚动和返回保存正常。
- [ ] 修改库存数量、名称、单位、日期后，缺料与待消耗清单同步变化。
- [ ] 删除某批食材后仍会统计其他可用批次；取消删除不改变数据。
- [ ] 清单更新不会扣库存；确认菜单后才按到期顺序扣减。
- [ ] 清楚区分本地缓存与内存数据，验证重新启动后的实际保存行为。
